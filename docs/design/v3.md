# oprobe 3.0 — architecture contract

Status: **binding** for all 3.0 work. Streams implement against this document; changes go through
the lead. Breaking changes from 2.x are allowed everywhere; nothing reads 2.x reports or flags.

Product line: *see every request your object-storage client makes; know where time and money go
and what to change — usable by people, CI and agents alike.*

Goals (owner): simple; agent-friendly; deep and complete observability; elegant, fast, native GUI;
a qualitative step in everything else. Out of scope for 3.0: distributed load generation (3.x),
code signing (no certificates), contributions to NSH upstream (draw what NSH lacks ourselves).

---

## 1. Concepts

| Concept | Meaning |
|---|---|
| **Target** | A named storage endpoint: URL + options + credential source. Stored in the config file. Any command taking a target accepts a target name, a URL (`s3://…`, `gs://…`, `azblob://…`, every OpenDAL scheme via `Operator::from_uri`), or `lab://[scenario]` (an in-process fault-injection server, no credentials/flags needed). |
| **Run** | One measurement. Immutable once finished. Has an id, the full resolved configuration, environment fingerprint, per-request trace, per-operation trace, report (aggregates, findings, cost). Persisted as one `.oprobe` file. |
| **Baseline** | A named set of runs (rolling window) that new runs are compared against. |
| **Finding** | A diagnosis item: stable `code`, severity, one-sentence cause, evidence (numbers + references to request/op rows or time windows), advice, and an optional *verification* (a concrete knob change / command that tests the advice). |

## 2. Run references

`RUNREF` := run id (`20261120-143005-a1b2`), unique id prefix, `last`, `last~N`, a label, or a path
to a `.oprobe` file. Resolved by `store::resolve_run(&str)`.

## 3. Storage layout

- Config: `$OPROBE_CONFIG` or `<config_dir>/oprobe/config.toml` (`dirs` crate):
  ```toml
  [defaults]            # applies to every run unless overridden
  output = "text"
  [targets.prod]
  url = "s3://bucket/prefix"
  region = "eu-west-1"
  endpoint = "https://…"           # optional
  credentials = "env" | "profile:NAME" | "anonymous"   # optional; default: provider chain
  options = { … }                  # OpenDAL options, validated against the service config
  ```
  Precedence: flags > `OPROBE_*` env > target > `[defaults]` > built-in. `oprobe config show`
  prints each effective value and its source.
- Data: `$OPROBE_DATA_DIR` or `<data_dir>/oprobe/`:
  - `runs/<run-id>.oprobe` — the run file (§4)
  - `runs/<run-id>.json` — sidecar summary for fast listing (id, label, target name/display,
    started_at, duration, verdict level, headline, ops/s, p50/p99, error rate, cost/month)
  - `baselines.toml` — `[baselines.<name>] runs = [ids…], window = 10`
- GUI preferences: NSH `Storage` (window placement, last tab, recent targets).

## 4. Run file `.oprobe` (format `oprobe.run/3`)

A zstd-compressed NDJSON stream. Line kinds, in order:
1. `{"kind":"header","format":"oprobe.run/3","run_id":…,"oprobe_version":…,"created_at":…}`
2. `{"kind":"report", …Report}` (§6)
3. `{"kind":"op", …OpRow}` × N
4. `{"kind":"req", …ReqRow}` × M

Readers skip unknown kinds. Writers write header+report last if streaming is needed (the store
writes a finished run in one go). Size target: ≤ 60 bytes/request compressed.

## 5. Trace data (in memory: `trace::log`)

Recorded for every measured operation and request, capped by `trace.max_requests` (default
1 000 000) with reservoir sampling beyond the cap (aggregates stay exact; the report states
`sampled: true` and the rate).

`ReqRow` (all times µs relative to the measurement window start; may be negative for warmup):
`t_us, op_id, attempt, api (OpenDAL ServiceOperation, e.g. "GetObject"), method, status,
protocol ("h1"|"h2"|"inproc"), reused, conn_id, remote (ip:port), queue_us, dns_us, tcp_us,
proxy_us, tls_us, send_us, ttfb_us, body_us, stall_us, total_us, bytes_up, bytes_down,
request_id?, retry_after_ms?, error_code?, tls?: {resumed, version, cipher?, hrr},
tcp?: {rtt_us, rttvar_us, retrans, cwnd, delivery_rate_bps}`

`OpRow`: `op_id, verb, key, t_us, latency_us, bytes, ok, error_code?, throttled, attempts,
breakdown: {queue_us, cache_us, backend_us, retry_us, client_us}, requests`

## 6. Report (`oprobe.report/3`)

JSON Schema generated with `schemars` from the Rust types; published by `oprobe schema report`.
Rules: every numeric field name carries its unit (`_us`, `_ms`, `_s`, `_bytes`, `_per_s`, `_pct`,
`_usd`, `_count`); no human-formatted strings in machine fields; enums are lowercase snake_case.

Top level: `schema, run {id, label?, started_at, ended_at, window_s, interrupted, sampled,
oprobe_version, host {os, arch, cpus, hostname_hash}, env {region?, provider?}}, target (redacted),
workload, knobs {requested, effective}, sla, verdict {level: ok|review|attention|critical,
headline, exit_code}, summary, stages (per-op breakdown shares incl. retry), apis[], verbs[],
connections, network {tls, tcp, remotes[]}, timeline[], heatmap {t_buckets_s, latency_buckets_ms,
counts}, findings[], cost {applicable, provider?, …}, slowest[] (op ids), cleanup, warnings[],
tune?`.

## 7. Events (`oprobe.events/1`, NDJSON on stdout with `--output ndjson`)

First line `{"type":"version","schema":"oprobe.events/1","oprobe":"3.0.0"}`. Every line has
`type` and `ts` (RFC 3339). Types: `phase {phase}`, `progress {elapsed_s, total_s?, ops,
requests}`, `interval {t_s, ops_per_s, mib_per_s, p50_ms, p99_ms, errors, throttled}`,
`finding {…Finding}`, `trial {…}`, `log {level, message}`, `result {run_id, path, report}`,
`error {error: ErrorBody}`. Consumers must ignore unknown types and fields. The same event enum
(`events::Event`) feeds the TUI/GUI (in-process) and MCP progress.

## 8. Errors and exit codes

`ErrorBody {code, message, hint?, retryable, docs?}`; `code` is a stable dotted string:
`usage.invalid_argument, usage.unknown_target, usage.unknown_run, config.invalid,
config.unknown_option, auth.no_credentials, auth.denied, net.unreachable, net.dns, net.tls,
net.timeout, storage.not_found, storage.throttled, storage.unsupported, safety.budget_exceeded,
safety.read_only, safety.refused, run.sla_failed, run.regression, run.interrupted, internal`.

Exit codes: `0` ok · `1` runtime failure (auth/net/storage/internal) · `2` usage/config ·
`3` SLA failed or regression · `4` budget exceeded · `5` safety refusal · `130` interrupted.
With `--output json|ndjson` errors are printed to stdout as `{"type":"error","error":{…}}`;
text mode prints `error: …` + `hint: …` on stderr.

## 9. CLI (3.0)

Global: `-o/--output text|json|ndjson|md|html`, `--color auto|always|never`, `-q`,
`--non-interactive` (implied when stdin/stdout not a TTY), `--config PATH`.

| Command | Purpose |
|---|---|
| `oprobe` | No args: GUI if a display is available, else the TUI; both start with onboarding when no runs exist. |
| `oprobe demo` | Starts `lab://demo` (throttling + stragglers), runs, narrates. Zero flags. |
| `oprobe run [TARGET]` | Measure. `--preset`, `--duration`, `--concurrency`, … ; `--existing PREFIX` (read-only); `--repeat N`; `--sla …`; `--baseline NAME`; budgets; `--dry-run`. Saves the run. |
| `oprobe tune [TARGET]` | Throttle-aware tuning; `--budget DURATION`; prints ETA up front. |
| `oprobe compare A B` / `--baseline NAME` | Regression gate (replaces `diff`); flags config differences; `--junit`, `--markdown`. |
| `oprobe runs list|show|open|export|rm|gc` | History. `export --format html|md|json|ndjson|csv|har|otlp`. |
| `oprobe analyze RUNREF` | Re-slice a run: `--by api|conn|remote|stage|second`, `--window A..B`, `--where …`, outlier attribution. |
| `oprobe explain RUNREF|FINDING_CODE` | Narrated causes + advice, or documentation of a finding code. |
| `oprobe target add|list|show|rm|test` | Manage targets; `test` = doctor. |
| `oprobe doctor [TARGET]` | Preflight: reachability, DNS, TLS (chain, expiry), clock skew, region, credentials (and their source), permissions (read/list/write/delete), provider capability matrix. |
| `oprobe probe URL` | Handshake microscope. |
| `oprobe watch TARGET` | Continuous low-rate probing, SLOs, Prometheus endpoint (`--listen`), OTLP push. |
| `oprobe matrix` | Same workload across targets / knob values / HTTP versions / addressing styles; ranked table. |
| `oprobe compat TARGET` | Correctness & compatibility suite (read-after-write, list consistency, conditional writes, multipart edges, checksums, redirects, versioning) → score. |
| `oprobe baseline set|list|rm|show` | Named baselines. |
| `oprobe lab` | Run the fault-injection server standalone. |
| `oprobe mcp` | MCP server (stdio; `--http ADDR` for Streamable HTTP). |
| `oprobe schema [NAME]`, `oprobe capabilities` | Self-description. |
| `oprobe config show|path|edit` | Configuration. |
| `oprobe cleanup` | Sweep leftover test data (dry-run first). |
| `oprobe self-update` | Check/download/verify/replace from GitHub releases (checksums). |
| `oprobe top`, `oprobe gui` | Interactive surfaces. |
| `oprobe completions SHELL`, `oprobe man` | Shell integration. |

Text output default: ≤ 20 lines, fits 80 columns: verdict → top findings (cause · evidence ·
advice · next command) → key numbers → "full report: oprobe runs show <id>".

## 10. Safety rails (engine-enforced, before and during a run)

`--dry-run` prints the plan (requests, bytes, objects written/deleted, estimated USD, ETA) and
exits. Budgets `--max-cost-usd`, `--max-requests`, `--max-bytes`, `--max-duration` stop the run
(exit 4). `--read-only` refuses every write/delete (exit 5); `--existing` implies it. Writes are
confined to `<prefix>/oprobe-run-<id>/`; `--idempotency-key K` names the run prefix so a retried
command resumes/cleans up instead of duplicating. Preflight (credentials, permissions, region)
runs before any write.

## 11. MCP (`oprobe mcp`)

Read-only unless `--allow-write`; budgets configurable as server flags. Tools (all with
`outputSchema`, `structuredContent` + short text): `doctor, probe_endpoint, plan_run, start_run,
get_run, cancel_run, list_runs, explain_run, analyze_run, compare_runs, start_tune, estimate_cost,
cleanup, list_targets`. Long-running tools return a run id immediately; progress via MCP progress
notifications; `get_run` polls. Resources: `oprobe://runs/{id}/report|events|slowest|html`,
`oprobe://schema/{name}`, `oprobe://docs/{topic}`, `oprobe://presets`. Prompts:
`diagnose-slow-reads`, `tune-for-p99`, `ci-gate-setup`.

## 12. Observability depth

- API attribution from OpenDAL `ServiceOperation` request extensions (fallback: URL heuristic).
- Capability-aware: operator `full_capability()` drives workloads, tuner candidates, doctor matrix.
- Retry bucket in breakdowns; per-stage p99; latency heatmap; per-remote-IP and per-connection
  splits; outlier attribution (attribute ranking of slow vs normal requests).
- TCP_INFO (Linux; macOS `TCP_CONNECTION_INFO`) per connection at request end; TLS handshake
  kind (full/resumed/HRR), resumption rate, cert chain in doctor.
- New workloads: delete (batched), copy, list paged (limit), presign GET, suffix footer reads
  (no HEAD), conditional writes, metadata-heavy.
- Exporters: OTLP traces (op = span, request = child span, stages = events) and metrics with OTel
  semantic-convention names; Prometheus text endpoint in `watch`; HAR; CSV; NDJSON.

## 13. GUI / TUI

Three panes: **sidebar** (Targets · Runs history · Baselines) · **run inspector** (tabs: Overview,
Requests, Timeline, Connections, Findings, Cost) · **inspector panel** (selected request/op).
New run = sheet; toolbar Run/Stop/Re-run/Compare. Honest charts only: straight/stepped lines,
real axes with units, log latency axis, no smoothing, hover readouts. Requests = virtualized
`DataTable` (100k rows). Timeline = canvas waterfall with zoom/pan and brush → outlier
attribution. Compare two runs. Command palette (mod+K). App menus and shortcuts per platform,
window/backdrop materials, persistence (`Storage`), notifications + dock/taskbar progress,
drag & drop `.oprobe`. TUI: same model, keyboard-first (r run, s stop, 1–6 tabs, / filter,
? help, q quit), adapts to 80×24, footer key hints.

## 14. Module ownership for parallel streams (B)

Shared core lands first (stage A2): `src/model/` (ids, ReqRow/OpRow, Report v3 types),
`src/trace/log.rs`, `src/store/` (config, targets, runs, baselines), `src/events.rs`,
`src/errors.rs`, `src/output/` (renderer plumbing), `src/guard.rs` (budgets, dry-run plan,
read-only), CLI skeleton with every §9 command wired (unimplemented ones return
`internal`/"not yet" until their stream lands).

| Stream | Owns |
|---|---|
| B1 Agent | `src/mcp/**`, `schema`/`capabilities`/`explain FINDING_CODE` commands, `AGENTS.md`, `docs/agents.md`, skill file |
| B2 Depth | `src/net/**`, `src/engine/ops.rs`, `src/engine/operator.rs`, `src/engine/workloads*`, `src/compat/**`, target URL resolution |
| B3 Analysis & export | `src/analysis/**`, `src/export/**`, `analyze`/`compare`/`baseline`/`watch`/`matrix` commands |
| B4 GUI/TUI | `src/ui/**`, `tests/ui.rs` |
| B5 Product | `src/report/**` (text/md/html renderers), `demo`/onboarding/preflight wiring, `target`/`config`/`runs`/`self-update` commands, `docs/**` (except design), README*, `.github/**`, `scripts/**`, `packaging/**` |

Cross-stream edits to `src/cli/mod.rs` dispatch and `Cargo.toml` are expected and merged by the
lead; keep them minimal and additive.
