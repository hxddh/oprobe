# oprobe 9.1 review: 9.0.0 bugs, simplifications, and nsh 0.7

Status: plan. Date: 2026-11-25. Basis: 9.0.0 (`9e0996e`).

The review had four sources:
- **A bug hunt.** It covered all 13 lab scenarios, `prove` on each, `show` (`--by`, ranges, multi-run), `--existing` / `--read-only`, budgets, SIGINT, corrupt and old files, `prove --save`, and an embedded `oprobe-trace` program. Every JSON output was validated against `schemas/`.
- **A code review of 7.1.0 → 9.0.0** (113 files, +12.8k lines). It looked for correctness, contract breaks, complexity creep and weakened tests.
- **A screenshot pass over the GTK app** under Xvfb.
- **An audit of nsh 0.6.1 → 0.7.0.**

The plan adds no new command, flag or concept. 9.1 keeps the v9 formats.

## What holds

- **Tests and contracts.** The test suites pass (cli 27, docs 6, core 263, trace), and every JSON output validates.
- **Old files.** trace/6–8 and old runs are refused with hints.
- **Overhead.** `memory://` costs 1.22 µs/op (budget 2).
- **`prove` results.** It proves demo (+34 %), stragglers (+92 %) and flaky (+610 %).
- **`prove --save`** keeps comments and `${ENV}`.

## 1. Bugs

### Data loss and wrong results first

| # | Bug | Evidence | Fix |
|---|---|---|---|
| D1 | **`prove --save` overwrites any existing file.** Any `.toml` path, or any existing file that is not the same service's op.toml, is rewritten as `base + edits`. That includes `config.toml` | `app/mod.rs:547-569` | Refuse an existing file that is not an `OperatorSpec` of the same service. Send `config.toml` to the `[operators.NAME]` branch |
| D2 | **A failing `--save` throws away a finished proof.** It runs before the proof is saved | `app/prove.rs:2110` vs `:2150` | Validate `--save` before the trials. Save the proof first; a save failure becomes a note |
| D3 | **A hint deletes an unrelated run.** For a `.prove.json` outside the store, the hint suggests `show --rm STEM`, and the stem prefix-matches a stored run | `app/runs.rs:518-524` | Suggest `--rm` only for a full prove id inside the store; otherwise say to delete the file |
| D4 | **`layers.cache.memory` caps entries, not bytes.** 1 KiB "fits" 26 GiB. `prove` sizes a budget that is never enforced, and the emitted Rust is unbounded | `operator/build.rs:304-308`, `operator/diff.rs:256` | Weigh entries by `v.len()` in the build and in the emitted Rust |
| D5 | **Real S3 throttling is missed.** A 503 `ServiceUnavailable` ("reduce your request rate") is not counted as a throttle | `oprobe-trace/src/rows.rs:404-411` | Exclude only `InternalError`. Add a lab case that answers `ServiceUnavailable` |
| D6 | **Aggregates-only traces give range and `--by` numbers from the slow-op rows alone**: 2 ops/s against a real 1 194 | `model/build.rs:338` vs `app/runs.rs:478` | Refuse when the trace kept no rows |
| D7 | **A cancelled `prove` leaves orphan trial runs**, which no `--rm` can reach | `app/prove.rs:1146,1172,1237` | Delete the trials on interruption, or save a partial prove |

## 2. App (screenshots)

1. **The headline repeats the top finding's first sentence word for word.** The finding's evidence paragraph is long, and its numbers duplicate the evidence table below it. Keep the headline, then drop the repeated sentence and the paragraph from the card; the table holds the numbers.
2. **Client CPU is drawn on the requests-in-flight axis** (0.5 cores on a 0–30 axis), so it is invisible. Give it its own small axis, or show it only when the client is saturated.
3. **Goodput, requests/s and throughput are the same shape** whenever an operation is one request of fixed size. Draw requests/s only when requests per op differ from 1. Throughput becomes a series of the goodput chart's right axis, or stays its own chart only when the sizes vary.
4. **The latency chart's p99.9 hides behind p99** when they are close. The tail plot's p99 mark is missing, since its label collides with p99.9. Offset colliding labels; dash p99.9.
5. **Connection counts disagree.** "27 dialed during warm-up" sits next to "retransmitting 0 of 29". The 29 counts the admin connections. Count only the measured operator's connections everywhere.
6. **The label "Requests on reused connecti…" is truncated.** Shorten it to "Reused connections".

## 2b. GUI and TUI: is every observed signal shown? (inventory + a real TUI session)

The GUI and the TUI share one view tree: `kit::in_terminal()` changes geometry, not content.
Nothing is gated off in the TUI, but the terminal geometry silently drops a lot.

**TUI defects** (seen in a 200×120 terminal):

| # | Defect | Cause | Fix |
|---|---|---|---|
| T1 | **The content cannot be scrolled from the keyboard.** PageDown and Space do nothing, Down moves the sidebar selection, and the sections below the first screen (distribution, heatmap, connections, details, setup) are unreachable without a mouse | No scroll keys are bound (`shell.rs:441-492`). The TUI pages the first scroll view in the layout, which is the sidebar | Bind PageUp/PageDown/Space/Home/End (and j/k) to the content scroll view, and make it focusable |
| T2 | **Every bar is blank**: time breakdown, per-verb, API p50/p99, hot-key meters and the waterfall. Only the numbers remain | Bar heights of 8–10 px round to 0 rows of 16 px (`profile.rs:1012,1777`, `kit.rs:587,624`) | At least one row in the terminal, or block glyphs (`█▌`) |
| T3 | **Axis labels collide** ("0/s0 s", "1.00 ms0 s", "0.011.00 ms") | The bottom y tick and the first x tick share a row (`chart.rs:394,412`); log ticks can land on one row (`chart.rs:342`) | Skip the x tick at x0, and drop y ticks that fall on the same row |
| T4 | **Rule labels overlap** ("pp99.9") | All labels sit at `y1+1`, at 6.6 px per char (`chart.rs:553-561`) | Stagger them by row, at 8 px per cell |
| T5 | **Labels are truncated** ("p99 with the reme…", "261…") | Property label is 18 cells (`kit.rs:567`); the Total column is too narrow (`profile.rs:358`) | Wrap property labels in the terminal; widen the column |
| T6 | **Unreliable quantiles look reliable**: they should be dashed and faint | Dashes are off in the terminal (`chart.rs:492`) | Use a dotted glyph instead |

**Signals captured but missing or weak in both front ends** (each fits an existing section):

1. **Integrity (corrupted objects) and SLA breaches.** The CLI shows them (`terminal.rs:542,787`); the app shows only the badge. Put a line in the trust notice or next to the verdict.
2. **APIs show only the top 3 status codes** (`profile.rs:377`). Show every code ≥ 400, plus the errors and throttled columns from `ApiRow`.
3. **The slowest 1 %'s stage split** (`TimeView.tail`) is dropped (`data.rs:403`). Draw it as a second stacked bar in "Where the time went".
4. **Capacity** (selected hypothesis, rate ceiling, in-flight ceiling) appears only inside a throttling finding. Show it as one property in Retries, plus ceiling rules on the in-flight and requests charts.
5. **Max (and p90) latency and missed arrivals** are not plotted. Add a faint max line on latency, and missed arrivals in "problems per second".
6. **Open-loop runs**: target, achieved and lag. Add a target rule on goodput and a property in Setup.
7. **The prove's sizing sweep is discarded** (`jobs.rs:355,394`). Plot objective against value with the knee marked. Show the prove notes and environment.
8. **Remotes, bytes and amplification sit in the closed Details disclosure**, and remote errors and p50 are not shown at all. Add a one-line summary that is always visible.
9. **A range selection changes only part of the page.** Retries, time breakdown, connections and details stay whole-run with no label. Recompute them for the range, or label them "whole run".
10. **The verb filter skips the heatmap**, and the distribution ignores the verb while a range is selected.
11. **The GUI chart issues** from §2: CPU on the in-flight axis, three look-alike charts, p99.9 hidden behind p99, connection counts that disagree.

The slowest-ops count also differs: the app shows 3, the CLI 1 or 5, and the view 5. Use 5 everywhere.

## 3. Simplify (code review, against v6 §1)

| Item | Action |
|---|---|
| Three save paths in `App` plus `toml_edit` | Keep one entry point (it fixes D1) |

**Weakened tests:**
- `tests/capacity.rs:83`: `<` was loosened to `<=`.
- The ceiling rule falls back to single arrivals.
- `prove --save` assertions run only when the verdict happens to be `improved`.

Restore each of them, and make the save test deterministic: use a lab and change that always improve, and assert that nothing is written when the verdict is not improved.

## 4. nsh 0.7.0

There is no changelog. These findings come from a source diff; `plot` is byte-identical, and the MSRV is still 1.97.

- **Breaking: window model v2.** `main_window()` is now an invisible host. A Rust root with no `window()` shows **no window** in the GUI. Wrap the app in `window().id("main")`, then move these from `main_window()` onto it:
  - attributes;
  - Dock and taskbar progress;
  - the close guard;
  - placement, which becomes `restore_bounds`;
  - full screen;
  - focus on open-files;
  - the sidebar's key-window state.

  Call `set_quit_mode(LastWindowClosed)`. Add `on_reopen`, which focuses the window; a second launch now fires `reopen`.
- **Compile fixes:**
  - `set_clipboard` returns a `#[must_use] Answer` (`profile.rs:999`, `operator.rs:272,277`, `store.rs:878`);
  - `drag` takes `DragOptions` (`tests/ui.rs:753,765,809`).
- **Adopt:**
  - `Button.busy` and `accessibility_hint` on Run, Prove and Save;
  - `Screen::accessibility()` / `layout()` and `window_ids()` in headless tests, which also catch a blank GUI;
  - `ClipboardWrite`, so "Copied" shows only when the write succeeded;
  - optionally, `nsh_base::TitleBar` instead of the hand-made insets.
- **Skip:**
  - `nsh_base::plot` (ours does more), DataTable `grow`, TUI image rendering, and the updater;
  - drop the unused `plot` feature.
- **Check:**
  - `cargo deny` and binary size: the TUI build now pulls in `image`;
  - by hand on macOS and Windows: progress, backdrop, close guard, the Settings window's parent.
