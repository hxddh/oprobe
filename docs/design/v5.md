# oprobe 5.0: architecture contract

**Status: binding** for all 5.0 work. It amends [v4.md](v4.md) and [v3.md](v3.md); anything not
changed here still holds. Breaking changes from 4.x are allowed everywhere: crates, run files,
reports, flags and JSON. Nothing reads 4.x run files. The evidence behind every item is in
[v5-review.md](v5-review.md), with IDs S·M·A·C·U·X.

**Theme: trustworthy, embeddable, at scale.**
- **Trustworthy.** 4.0 gave oprobe one model and one verification loop, but the model knew only one
  kind of limit and `verify` confirmed changes that lost half the throughput. In 5.0, oprobe fits
  competing hypotheses to the data, tests them with experiments, and gives a net verdict with
  honest uncertainty.
- **Embeddable.** The instrumentation becomes a library that production OpenDAL clients can run.
- **At scale.** Load can come from many machines, and from clients other than OpenDAL (the AWS SDK,
  boto3, AWS CRT).

**Owner decisions:**
- the security fixes ship in 5.0;
- the crates are split for embedding;
- distributed load and multiple clients are in scope;
- no container image, Helm chart, Grafana pack or canary service;
- no code signing;
- everything listed here ships in 5.0.

## 1. Workspace and crates

```
Cargo.toml                 [workspace] members = ["crates/*"]
crates/oprobe-trace/       embeddable instrumentation (publishable library)
crates/oprobe-core/        engine, analysis, model, store, tune, lab, app service layer (library)
crates/oprobe/             the `oprobe` binary: cli/, mcp/, ui/ (features: tui (default), gui)
```

### `oprobe-trace`
- **Purpose:** what an application adds to its own OpenDAL operator in production.
- **Contents:**
  - `TraceLayer` (OpenDAL layer);
  - the fidelity HTTP client (`HttpFetch` built on reqwest, with phase timing);
  - `ReqRow` / `OpRow`;
  - an always-on `Recorder`, not tied to one run, with bounded memory;
  - aggregates (DDSketch or HDR per api × stage);
  - an `otel` feature that emits OpenTelemetry metrics and spans, following HTTP semantic
    conventions (`http.client.request.duration` plus `oprobe.*` stage attributes);
  - an exporter hook.
- **Dependencies:** no clap, rmcp, UI or zip.
- **Public API:**
  ```rust
  let (layer, handle) = oprobe_trace::layer(Config::default());
  let op = op.layer(layer);
  // later
  handle.snapshot();
  ```
- **Overhead budget:** ≤ 2 µs/op on memory:// (4.0 measured 9 µs), and reported.

### `oprobe-core`
- **Purpose:** everything the binary does, except its front ends.
- **Service layer:** `oprobe_core::app` is the only entry point for front ends. The CLI, MCP and the
  UI all call it, and none of them builds clap structs any more.
  ```rust
  pub struct App { paths, config, … }
  impl App {
      async fn plan(&self, req: RunRequest) -> Result<Plan>;
      async fn run(&self, req: RunRequest, sink: EventSink, cancel: Cancel) -> Result<RunOutcome>;
      async fn tune(&self, req: TuneRequest, …) -> Result<TuneOutcome>;
      async fn verify(&self, req: VerifyRequest, …) -> Result<VerifyResult>;
      async fn fix(&self, req: FixRequest, …) -> Result<FixOutcome>;
      async fn compare(&self, req: CompareRequest) -> Result<Comparison>;
      // plus: explain, analyze, doctor, sample, discover, targets, runs, baselines, cleanup
  }
  ```
  - `RunRequest` is a `RunSpec` (4.0) plus overrides plus safety (budgets, read-only, allow-write)
    plus a client choice (§7) plus workers (§8).
  - MCP calls `App` in-process. Child processes are gone, and long work runs as jobs (§9).

### `oprobe` (binary)
- `cli/`, `mcp/` and `ui/` are thin adapters over `App`.
- Release profile: `codegen-units = 1`, `lto = "fat"`, `strip = true`, `opt-level = 3`.
  - Size target: ≤ 45 MB for the CLI+TUI musl binary (4.0: 74 MB).
  - Optional services sit behind cargo features; the default set covers the common clouds.

### Splitting the large files
- **Done by the foundation:** the compare/gate logic moves from `report/diff.rs` to
  `analysis/gate.rs`, and a shared presentation model is added (`report/view.rs`: one view per
  report section, used by terminal, Markdown, HTML and the UI).
- **Done by the owning streams:** `mcp/tools.rs` is split per tool family, and `findings.rs`
  per finding family.

### Publishing
- crates.io gets `oprobe-trace`, `oprobe-core` and `oprobe` when a token exists. The release
  workflow publishes them in order.

## 2. Run file and report v5

**Run file (`oprobe.run/5`)** is a zstd stream of segments, so it is written while the run is in
progress and the process never encodes the whole file in memory:
- `header` (with the spec and the client);
- `segment` blocks: columnar op and request rows for one time slice, interned strings, `u32`
  microseconds;
- `interval` blocks: per-second sketches;
- `report` at the end.

**Sampling keeps whole operations:**
- an operation is kept with all of its requests;
- the sample is a reservoir stratified by time;
- the always-kept set holds the slowest 1 % and every failed or throttled operation;
- `report.sampling { kept_ops, seen_ops, ratio }`.

Findings use aggregate counts, never sampled counts (fixes M2).

**Memory targets:** an hour-long run stays under 150 MB RSS, and the App can open a run of 1 M
requests in under 300 MB, with a columnar in-memory view (fixes M3).

**Report (`oprobe.report/5`)** adds:
- `capacity.hypotheses` (§4);
- `schedule` (§3);
- `client` (§7);
- `workers` (§8);
- `dimensions` (§3);
- `sampling`;
- `self` (observer cost and runtime health).

## 3. Measurement

### Open loop (fixes M1)
- **Arrival shapes:** `--rate N` with arrivals that are `constant` or `poisson`; `--shape
  ramp:FROM..TO/D | step:… | diurnal`; and `replay:FILE`.
- **New `schedule` stage:** the time from an operation's intended start to its actual start.
- **Missed arrivals:** arrivals that never started are counted as censored latencies with a lower
  bound of (window end − intended start). They are included in the tail as "≥" values, and
  `missed_arrivals_ratio` is reported.
- **Guard:** when `missed_arrivals_ratio > 1 %`, capacity advice is suppressed and the
  `schedule_backlog` finding explains the backlog.
- **Closed loop:** these runs say they are closed-loop and therefore subject to coordinated
  omission.

### Kernel timing (fixes M4, M9)
- **Upload end:** at response headers, read `tcpi_bytes_acked`, `tcpi_notsent_bytes` and `unacked`
  (Linux), `tcpi_txbytes` / `snd_*` (macOS), or `SIO_TCP_INFO` v1 (Windows). From these, estimate
  `upload_acked_us`: the last request byte acknowledged by the server.
- **Phases:** `send` becomes `upload` (to the acknowledgement), and `ttfb` becomes `server` (from
  the acknowledgement to the first byte).
- **RTT:** use `min_rtt` for network RTT. Keep `notsent`, `lost`, `bytes_acked` and `pacing`.
- **Retransmits:** attribute them per request with no `MAX_AGE` skip.
- **Windows:** gets TCP info.

### HTTP/2 (fixes M5, M6)
- **Microscope transport:**
  - a pool of several HTTP/2 connections per host, sized by `max_concurrent_streams`;
  - waiting in `ready()` counts as a new `stream_wait` stage;
  - the body is sent in frames.
- **Fidelity transport:** a request that waits on another request's connection setup is marked
  cold, and that wait goes to `connect`.
- **Metrics:** stream concurrency, and flow-control stalls (time with the window at 0).
- **Lab:** `lab://NAME?proto=h2|h2c|https`, with ALPN; preflight checks the protocol.
- **Microscope's role:** a diagnostic mode, with its overhead reported. Fidelity stays the default.

### Self-observation (fixes M7, M8, X6)
- **`report.self`:**
  - observer cost in µs/op, measured;
  - tokio runtime busy ratio and global queue depth;
  - a 1 ms scheduling-lag probe (p99);
  - client CPU per second, measured after warmup;
  - current and peak RSS.
- **Saturation flag:** when lag p99 > 5 ms or CPU is ≥ 90 % of the cores in use, set
  `client_saturated`. The server/TTFB stage is then flagged as unreliable, and `client_cpu`
  overrides the bottleneck verdict.
- **Recorder hot path:**
  - aggregates per shard, merged at snapshot time;
  - `&'static str` keys;
  - no allocation per request.

### Server signals (fixes M10)
Each request records:
- the S3/GCS/Azure error code parsed from the error body, capped at 4 KiB;
- `x-amz-id-2` alongside the request id;
- the region (`x-amz-bucket-region`);
- `server-timing`;
- the CDN cache status.

### Resolution (fixes M11)
- **Timeline:** p50, p90, p99, p99.9 and max at full precision.
- **Per-second series:** in-flight, connections, CPU, throttled, errors and missed arrivals.
- **Long runs:** resolution adapts — 1 s for the first 10 minutes, then 10 s.
- **Heatmap:** built from interval sketches, not from sampled rows.

### Dimensions (fixes M12)
- `report.dimensions` has slices by prefix (depth configurable), hot keys (top 20 with share and
  throttle share), object size bucket, cold vs warm (first read of a key vs repeat), and tenant.
- Every finding can name the slice that drives it.
- Datasets can use size distributions: `--object-size dist:lognormal(…)|file:…`.

### Workloads and semantics (fixes M13, M14, M15)
- **Replay of real traffic:**
  - S3 server access logs, CloudTrail (S3 data events), and oprobe traces;
  - `--replay FILE [--speed N] [--map-prefix A=B]`;
  - safe by default: writes are refused unless they target the run prefix.
- **Format range patterns:** `parquet` (variable footers), `orc`, `lance`, `zarr`, `video-hls`.
- **Semantics probe** (`oprobe probe semantics`):
  - read-after-write;
  - list-after-write;
  - conditional writes (`if_none_match`, `if_match`);
  - versioning;
  - append and rename where the capability exists.
- **OpenDAL reader options:** prefetch and stream (read-ahead) settings become knobs.
- **Concurrent-limit layer:** measured as a knob.
- **Cold start:** connection-setup cost is reported separately, from a cold-start sample taken
  before warmup.

## 4. Analysis: hypotheses, experiments, net verdicts

### Limit models (fixes A1, A3, A5, A7, A8, A9)
- `capacity::fit(reqs, ops, dims) -> Vec<Hypothesis>` fits five limit models side by side:
  - `InflightLimit { ceiling }`;
  - `RateLimit { rps, burst }` (token bucket; the throttle share depends on the accepted rate per
    window);
  - `KeyLimit { key/prefix, rps }`;
  - `Queueing { service_ms, servers }` (latency grows with in-flight: TTFB vs level curve);
  - `BandwidthCap { bytes_per_s }` (aggregate bytes/s flat across streams).
- **Also checked:** `ClientBound` (from `client_saturated`), `Time-varying` (change-point
  detection on the limit), and `None`.
- **Hypothesis:** `{ kind, params, log_likelihood, evidence[], confidence, explains_ratio }`.
- **Selection:** the best hypothesis is chosen by penalised likelihood. The alternatives are listed.
  No limit is asserted below medium confidence (the advice then says "inconclusive: run
  `oprobe probe limits`").
- **Prediction:** `predict(knobs)` uses the fitted model, with Little's law on the measured latency
  curve and backoff excluded from service time.

### Adaptive experiments (fixes A1, A4)
- `oprobe probe limits TARGET`, and an automatic phase at the start of `fix`/`tune`.
- **Within one run:** step concurrency and rate up and down (a staircase with plateaus).
- **Output:** the latency-vs-load curve and the limit type, identified directly.
- **Budget:** capped by the safety budget.

### Tune 5 (fixes A4, A11)
- **Optimiser:** Bayesian optimisation, with a Gaussian-process surrogate over
  `{concurrency, rate, max_inflight, io_concurrency, range_gap, http_version, retry backoff}` and a
  throttle-risk constraint.
- **Headroom:** a posterior quantile (`--risk 0.05`), not a fixed 15 %.
- **Budget:** goodput is scored net of retry cost. `--max-throttle-ratio` stays as a hard cap
  (default 0.5 %).
- **Capacity pooling:** trials are pooled per-trial window, never with `Window::all()`.

### Verify 5 (fixes A2, A12, U2)
- **Sequential test:** an SPRT with interleaved A/B pairs and early stopping, at `--repeat` minimum
  2 and maximum 8.
- **Two-sided net verdict:** `improved | regressed | traded | no_change | inconclusive`.
  - `traded` lists what got better and what got worse, e.g. "throttling −4.6 pp, goodput −21 %".
  - The finding's `expect` must be met within its interval. A measured interval that misses the
    predicted one refutes it.
- **Intervals:** bounded intervals for ratios (Wilson/beta) and log-ratio intervals for
  throughput. No impossible CIs.
- **Consistency:** the UI and compare show the same net verdict.

### Fix 5 (fixes C3)
- **Output:** a menu of 2–4 Pareto options, each with goodput, p99, throttle %, cost/month and
  verify status. Example: "0 % throttling at −28 % goodput, or 0.4 % throttling at −3 %".
- **Defaults:** the recommended option is the best goodput within the risk.
- **Never:** recommends a change whose predicted outcome is worse on the objective.

### Compare and gate (fixes A12, A13, U3)
- **Three tiers:** `fail` (significant and over the limit), `warn` (significant, under the limit),
  `pass`. There is also an explicit `inconclusive` state, which is never shown as "same".
- **Trend gate:** drift from the baseline history (EWMA, change-point detection).
- **Floors:** noise floors per target from history.
- **Interval methods:** the same as verify.

### Findings (fixes A6, A10, A15)
- **5xx errors:** always reported, even with throttling.
- **Tail attribution:** stage shares include backoff and schedule.
- **Attribution evidence:** requires significance (a Fisher test on the counts).
- **`cache_opportunity`:** not emitted on generated datasets smaller than the working set the user
  stated.

### Cost (fixes A14)
- Bill-grade cost: storage classes (standard, infrequent access, archive) with minimum billable
  size and minimum duration; retrieval fees; egress tiers and free tiers; inter-region transfer;
  failed-request pricing per provider.
- Each Pareto option shows its monthly impact in dollars.

### Lab parity (fixes X8)
- `src/lab` (now a module directory) can inject: rate limits (token bucket), queueing (an M/M/c
  server), aggregate bandwidth caps, time-varying limits, per-key/prefix limits, 5xx mixes, h2, and
  https.
- `tests/convergence.rs` has one case per fault. Each asserts:
  - the right hypothesis is chosen;
  - following the advice improves or trades as predicted;
  - verify's net verdict is correct.

## 5. Security (all of S1–S7)

### MCP
- **Target overrides:** without `--allow-target`, overrides of `endpoint`/`proxy`/`insecure`/
  `options` on a configured or credentialed target are refused. They are allowed only with
  `anonymous` or on `lab://` / `memory://` targets.
- **`probe_endpoint`:** refuses link-local, loopback (except lab) and private ranges unless allowed.
- **HTTP transport:**
  - a bearer token is required: generated at start and written to `<data>/mcp-token` with mode
    0600, or set with `--token-file`;
  - `--http-allow-remote` requires TLS or an explicit `--insecure-remote`;
  - connection limits and timeouts.
- **Default budgets:** 50k requests, 2 minutes, $1 and 5 GiB. They can be raised only by server
  flags, never by a tool call.
- **Untrusted text:** object keys, error bodies and server messages are escaped, truncated, and
  placed only in `structuredContent` under `untrusted` fields. The skill documents this.

### Lab
- Loopback only, unless `--bind` is given together with `--allow-remote`.
- Body and store size caps.

### Store
- Config and credential-bearing files are written 0600.
- A warning is printed when secrets are inline. `${ENV}` and profiles are documented as the safe
  way.

### Supply chain
- Actions are pinned by SHA, with Dependabot updates.
- No caches in release jobs.
- A `cargo deny` job checks advisories, licenses and bans. RUSTSEC-2023-0071 is fixed, or
  documented with a mitigation if no fix exists.
- `install.sh` and `self-update` verify the GitHub build-provenance attestation when `gh` or
  sigstore verification is available. Otherwise they verify a minisign signature over `SHA256SUMS`;
  the release signs it with a key stored as the `MINISIGN_KEY` secret, and the public key is
  embedded. The minisign step is skipped with a warning if the secret is absent.

## 6. Agents and automation

### MCP
- **Tool list size:** `tools/list` is at most 60 KB. Output schemas use `$ref` to resource schemas,
  and the report schema is not inlined.
- **Jobs:** every long operation (run, tune, verify, fix, probe limits, distributed run) is a job,
  polled with `get_run` and reporting progress. No tool blocks for longer than 5 s.
- **Response size:** responses are summaries by default, with `detail: summary|full` and cursor
  pagination for lists, rows and resources. Text and structured content are not duplicated.
  `get_run` defaults to the summary.
- **New tools:**
  - `ask_run`: questions in natural language over a stored run; answers cite the evidence fields;
    it is deterministic, retrieval over the report, with no LLM inside;
  - `save_target`;
  - `apply_profile`: writes a profile or target change and returns a diff; needs `--allow-write`.
- **Next steps:** every `next` step has an MCP call, and error hints are MCP-aware.
- **Child runs:** verify and fix child runs are hidden from `runs list` and `last` (`parent_run`
  field, `--all` to show them).

### CLI
- **Brief output:** the text brief wraps to the terminal width (or 100 columns when not a
  terminal) and never truncates commands.
- **Help:** `--help` shows the common flags. `--help-all` and the help headings show the rest.
- **Flags:** units are consistent; throttle flags are one pair (`--max-throttle-ratio`); `--p99-ms`
  style everywhere.
- **Completions:** dynamic, for target names and run ids.
- **i18n:** a message catalog with English and 简体中文. The language comes from `--lang` or
  `LANG`/`LC_ALL`, or the OS locale in the App. It covers the brief, findings' cause and advice,
  errors and hints, and the App. Machine output stays English.

### Automation
- **action.yml:** `--strict`; the data directory is cached across jobs (noise and capacity
  history); `repeat` and `calibrate` inputs.
- **watch exports:**
  - OTLP: a stable `service.instance.id` and target attribute (no run id per window), cumulative
    counters, `OTEL_EXPORTER_OTLP_HEADERS`, and protobuf.
  - Prometheus: target label, `oprobe_build_info`, last-success timestamp, `/healthz`, HELP text.
- **Out of scope** (owner decision): a canary service, images, Helm and dashboards.

## 7. Clients: what generates the load (new)

- `--client opendal` (default; white-box phases).
- `--client aws-sdk` uses aws-sdk-s3 (Rust) with oprobe's instrumented hyper connector, so
  phases are kept.
- `--client exec:CMD` uses the **oprobe client protocol**:
  - oprobe spawns CMD and sends operations as NDJSON on stdin (`{id, op, key, range, size, …}`);
  - the adapter replies with NDJSON results (`{id, ok, status, bytes, t_start_us, t_end_us,
    phases?: {…}, attempts, error?}`);
  - this is versioned and documented in `docs/clients.md`.
- **Reference adapters** under `adapters/`:
  - `boto3` (Python; phases from botocore event hooks);
  - `awscrt` (Python awscrt S3 client; transfer metrics);
  - `go-sdk` (aws-sdk-go-v2 with its httptrace hooks).
- **Report:** `report.client { kind, version, phases_available[] }`. Findings that need phases the
  client cannot provide are suppressed, with a note.
- **Comparing clients:** `oprobe compare` across clients is allowed (same target and workload,
  different client). This answers "is my SDK the bottleneck?".

## 8. Distributed load (new)

- **Worker:** `oprobe worker --listen ADDR --token-file F` serves the worker protocol (HTTP/2 +
  JSON). TLS is optional (`--tls-cert`); the token is required.
- **Coordinator:**
  - `oprobe run … --workers host:port,…` (or `[workers]` in the config) checks every worker
    (version, clock offset via NTP-style ping exchange, capabilities);
  - it splits the spec: dataset partitions by key range, and concurrency and rate divided by
    weight;
  - it starts the workers at a common instant;
  - it streams the workers' interval sketches live and collects their segments at the end;
  - it merges them into one run with `report.workers[]` (per-worker summary, clock offset, skew
    warnings) and a per-worker dimension.
- **Safety:** budgets are global and enforced by the coordinator (workers get a share and report
  progress every second). Cancelling fans out to every worker. Cleanup is coordinated, so a worker
  only deletes its own prefix.
- **Local mode:** `--workers local:N` spawns N local worker processes, for testing and to use more
  cores.
- **Tests:** coordinator plus 3 local workers against the lab. The merged counts must equal the sum,
  the capacity fit must work on merged rows, and cancel and budget breach must stop every worker.

## 12. Streams and ownership

- The workspace split into three crates. `oprobe-trace` gets an always-on recorder and a public
  layer API.
- The `app` service layer, with every CLI command routed through it, and MCP and the UI using it
  (no child processes, no clap structs).
- Run file and report v5 types: segments, whole-op sampling, `Hypothesis` /
  `NetVerdict` / `ClientInfo` / `WorkerInfo` / `Dimensions` / `SelfStats` types, with the logic
  stubbed.
- `analysis/gate.rs`, `report/view.rs`, `src/lab` as a module directory.
- Release profile and size.
- Schemas blessed and all tests green.
