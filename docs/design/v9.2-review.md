# oprobe 9.2 review: what 9.3 should be

Status: plan, accepted by the owner on 2026-11-26 (the K4 recommendations included). Date: 2026-11-26. Basis: 9.2.0 (`976b501`).

The review had three sources:
- **A bug hunt** on the 9.2.0 binary: all 13 lab scenarios, 12 proves, budgets, SIGINT / SIGTERM /
  SIGHUP mid-run and mid-prove, open loop, `show` in every mode, about 30 malformed files and a
  200-case mutation fuzz, `--set` validation, secrets, and every `-o json` output validated
  against `schemas/` (25 documents).
- **A code review of 9.1.0 → 9.2.0** (`fc22b3e..976b501`): engine, guard, store and app in one
  pass; `oprobe-trace`, operator, prove and findings in another. OpenDAL 0.59.5, hyper-util, tokio
  and foyer sources were read where a claim rests on them.
- **The three CI failures of 9.2** (a throttle proof on Linux, a queueing finding on Windows, a
  parquet proof on macOS): all three were lab scenarios sitting on a threshold.

Each item says how sure it is: **reproduced** (run twice on the binary), **read** (the code path
traced end to end), or **suspected** (what would confirm it is named).

## Direction

9.2 hardened what oprobe does to a target and what `prove` may claim. The review found that the
weakest part of the loop is now **Explain**: several findings say the wrong thing on ordinary runs,
and a few stop paths still leave data behind.

**9.3 is a truth-and-stop release.** No new command, no new flag, no format bump:

1. **Stop safely on every path** (stream K1).
2. **Findings that say what happened** (stream K2).
3. **A proof that is honest about failures, time and stopping** (stream K3).
4. **Close what 9.2 left half-open** (stream K4: four owner decisions).
5. **Tests that do not depend on the machine** (stream T).

**Not in 9.3:** new presets, finding codes or output formats (v6 §1); a second rewrite of the
prove statistics (the boundary is conservative, about 0.5 % real false positives; collect use
first); more than one cache shard (no benchmark says the single lock hurts).

**Binary size has no hard target any more** (owner decision, 2026-11-26): size must not cost
usability or function. CI keeps reporting it. v6 §4, `Cargo.toml` and `ci.yml` say so now.
9.2.0 is 55.9 MB with the app and 23.9 MB CLI-only.

## What holds

- **Labs.** The top finding matches the fault on demo, throttle, stragglers, parquet, ratelimit,
  hotkey, bandwidth, timevarying and noisy. Every printed `next` ran as printed.
- **Proves.** Nine of nine decided `improved` on the first try, the 48-worker `lab://throttle`
  included. `prove --max-duration` was never overshot.
- **Budgets.** Small `--max-requests` / `--max-bytes` on `large-objects` stop the run, exit 4, save
  a partial run and clean up; totals agree across verbs, APIs and timeline.
- **Signals.** SIGINT, SIGTERM and SIGHUP exit 130 in about 0.15 s with the partial run saved and
  nothing left on the target (with stderr open: see K1-1).
- **Untrusted input.** Every malformed file gives `usage.invalid_argument`, exit 2, under 0.1 s;
  the fuzz found no panic or hang (but see K1-6 for memory).
- **Secrets.** No secret option, `${ENV}` value, presigned parameter or `user:pass@` appeared in
  stdout, stderr or any stored file.
- **JSON.** All 25 documents validate. stdout carries only the result.
- **Layer order** against OpenDAL 0.59.5: no operation kind is worse than in 9.1.
- **Verdict statistics.** The `CRITICAL` index, the crossover variance for unequal counts and the
  convergence series are right; a bimodal p99 under the null stays under 5 %.
- **Dial claims and the retransmit ledger**: lock order, single charge and conservation hold.

## Papercuts (one pass)

`--pairs` is hidden from `prove --help` though the docs cite it, and above 12 it is clamped
silently; two docs examples fail as written (`r2://` without an account id); an unreachable proxy
is reported as the endpoint; `lab --bind` on a busy port is `internal` with no hint;
`show --rm X X` fails on the second X; an interrupted prove says "partial results" though nothing
is saved, and says "Ctrl-C" for SIGTERM; a 0-pair prove still offers a `next`; a prove of a run
whose secrets were given by value fails without saying they were not stored; connection counts
still disagree in `--detail` (9.1 review §2 item 5); `show --list` pads the proves table to 300
columns.

## Plan for 9.3

| Stream | Items | Size |
|---|---|---|
| **K1: stop safely** | K1-1 … K1-10 | medium |
| **K2: findings** | K2-1 … K2-11 | large; the centre of the release |
| **K3: prove** | K3-1 … K3-9 | medium |
| **K4: decisions** | K4-1 … K4-4, once decided | small to medium |
| **K5: trace, privacy** | K5-1 … K5-5 | small |
| **T, S, papercuts** | all | small each |

Order: K1-1, K1-2 and K1-3 first (small fixes, real targets at risk), then K2, then K3.
Each fix comes with a test that fails on 9.2.0; items marked "suspected" are confirmed or dropped
before they are fixed. The engine keeps its synchronized worker start: it is what a batch job
does, and `layers.retry.jitter` is the remedy the herd is evidence for. Using the warm-up ramp for
the capacity fits (a run would then vary its own load) is a design item for after 9.3.
