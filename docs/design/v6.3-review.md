# Review of 6.2.0, and the plan for 6.3

This review applies the owner's three bars to oprobe 6.2.0:

1. **Easy to use, not complicated.**
2. **Observability that is clear, complete and fine-grained, charts included.**
3. **An app with native quality that follows each platform's interaction and design guidelines.**

Method: there were three independent reviews (usability, observability, native/HIG), plus my own
walkthrough. The review ran hands-on lab runs and real CLI journeys, read the code, and took GTK
screenshots under Xvfb. I spot-checked every finding marked high against the code. Evidence is
given as `file:line`, as of commit 2db1599 (6.2.0).

macOS and Windows were not run. The findings marked **(mac/win)** come from reading the code paths
that Linux tests do not exercise.

## Already fixed: the macOS menu bar (PR #24)

On macOS the app had no Settings, no New Run and none of its own shortcuts. The cause was the
sidebar shortcut `"ctrl+mod+s"`, which `MenuItem::shortcut` panics on. `MenuItem::shortcut` checks
a shortcut by the off-macOS rules, where `mod` means Ctrl, so the string reads as Ctrl twice. The
menu bar was never built, and AppKit kept its default menu.

The fix names Command instead (`ctrl+cmd+s`). There is a unit test over every shortcut on both
platforms, and a headless UI test that runs as macOS (⌘, ⌘N ⌃⌘S).

**Lesson.** Platform branches need tests that run as that platform. The headless engine can do
this: `Environment.os`.

## 1. Usability

**The first impression fails.**
- README and getting-started promise `demo` → `prove last` → `proved +31 %`. The real result is
  `inconclusive +1.5 % [−5.7, +9.2]` after about 70 s.
- The demo is labelled CRITICAL for 0.3 % throttling, and fixing that throttling changes nothing
  measurable.
- Severity follows the presence of 429/503 responses, not their cost (U-H1).

**The app and the CLI prove different things.**
- The app's "Apply" invents values: `suggested()` sets `concurrent_limit.http = 16`, `timeout.io =
  5s` and so on (`ui/store.rs:626`).
- It then proves them as `--with`, so sizing is skipped (`app/prove.rs:741`). The CLI sizes the
  same remedy (24).
- This breaks "only prove gives a number" (U-H2).

**Two budgets and dead hints.**
- `prove` has both `--budget` and `--max-duration`.
- Warnings name `--warmup`, which `prove` does not take and `run` hides.
- The dry-run ETA covers one trial, not the whole proof (U-H3).

**Text output clips itself.**
- When piped, `show` truncates the very command it suggests, and drops finding codes (U-H4).

**One concept, several names.**

| Concept | Brief | List / JSON | App | Docs |
|---|---|---|---|---|
| Verdict | `[HEALTHY]` | `ok` | "Healthy" | |
| Prove result | | `improved` / `worse` | "proved" / "refuted" | |
| A trial | "trial runs" | | "replays" | "A/B pairs" |

- The interval is described as Student's t in one doc and as Wilson in another (U-M1).

**Remedies are noisier than the contract.**
- `tail_stragglers` changes two paths.
- Diffs print every default value, e.g. the whole `retry = {…}` table (U-M2).

**New Run in the app is less safe than the CLI.**
- There is no plan or dry-run preview and no budget.
- There is no picker for configured operators or `op.toml` (U-M3).

**Vestiges of 5.x.**
- SLA lines (`sla ✓ met …`) and `--set sla`.
- Labels that are documented but cannot be set.
- About 14 dead 5.x finding titles in the catalog.
- Two ways to declare an operator: `op.toml` and `[operators.NAME]` (U-M4, M5, M7).

**Errors.**
- A wrong S3 key prints a 900-character OpenDAL dump; the S3 code (`InvalidAccessKeyId`) is at the
  end (U-M6).
- With 0 A/B pairs, the result still prints a diff that looks like a finished proof (U-L1).
- The CLI lab has 13 scenarios; the app offers 6 (U-L2).

## 2. Observability

**Three timeline series are misleading.** I verified each in `oprobe-trace/src/recorder.rs`.

- **"Goodput" per second counts failed operations.**
  - The series is `b.ops / width`, failures included (`:1336`).
  - The summary's goodput excludes failures (`:1362`), so the chart and the tile disagree whenever
    errors happen.
- **"Throttled per second" counts operations, while the chart says responses.**
  - `b.throttled` goes up once per operation (`:1015`).
  - In the throttle run the series sums to 22, against 41 throttled responses.
- **Events land in the second the operation started.**
  - Buckets use `c.started` (`:941`, `:1009`).
  - A 503 or a failure at +7 s is drawn at 0 s, so a rate-limit plateau or a burst is smeared
    back to its origin.

**What is missing.**
- **Requests per second, and retries per interval.** Rate limits are in requests per second, yet
  the default `lab://ratelimit` is diagnosed as an in-flight limit.
- **Series per verb or per API.** A mixed run blends into one latency line.
- **Per-request network and server signals.** rtt, min_rtt, retransmits, Server-Timing and the
  provider error code (`SlowDown`) are recorded but never aggregated or shown. They are what tells
  "network slow" from "server slow".

**Unused evidence.**
- `FindingView.op_ids`, the example operations behind each finding, is never drawn.
- `analysis::segments::fine_heatmap` has no caller.

**Too coarse.**
- The heatmap and the fallback CDF have 20 rows in 1-2-5 steps, each a 2–2.5× ratio: 6.6 ms and
  9.9 ms fall in one cell.
- The run's HDR histogram exists in the recorder but is not kept in the report.
- The five slowest operations are often five copies of one cause.

**Statistics.**
- Per-second p99.9 is the maximum when a second has fewer than about 1000 operations.
- Compare colours single-run deltas at a fixed ±2 %, well inside run-to-run noise.
- `tail_stragglers` takes quantiles from sampled rows without weights. The sampler always keeps
  the slowest rows, so this over-weighs the tail.

**Interaction.**
- Every chart is a static picture with its own hover readout.
- There is no shared crosshair and no way to brush a time range and see everything for it.
- There is no drill-down from an aggregate (a heatmap cell, an API row, a finding) to the requests
  behind it, and no filter by verb, API, status or key.
- The heatmap has no colour legend.

**Smaller issues.**
- The `throttled` column means a share of all throttling for hot keys, but a share of the slice's
  own requests for prefixes and sizes.
- The `repeated_reads` text names the wrong unit.
- `key_limit` prints its remedy twice.
- `tail_stragglers` names one API when all are affected.
- In the CLI, the timeline says "per second" for 10 s rows and prints about 900 rows for a one-hour
  run.

## 3. Native quality (macOS, Windows, GNOME)

**The sidebar material never shows (mac/win).**
- The root paints an opaque background over the whole window (`ui/mod.rs:138`).
- The sidebar is transparent over the root, so it shows white instead of vibrancy or Mica.
- Windows should use `Backdrop::Window` (Mica), with a fallback before Windows 11.

**The sidebar is not a list.**
- Every row is its own button and Tab stop.
- There are no arrow keys, no Shift-extend, no type-select, no Delete, and no `Listbox` / `Option`
  roles.
- Screen readers hear "button" rather than "row 3 of 12, selected".

**Destructive actions break the guidelines.**
- ⌘⌫ / Ctrl+Backspace delete runs while the user is typing in a field: menu shortcuts default to
  `When::Always`. Opening the Delete dialog then also replaces the open New Run form.
- Delete is a hand-drawn modal, not the platform alert. `nsh_base::alert_dialog` maps to NSAlert,
  TaskDialog and AdwAlertDialog.
- On Windows the destructive button is first in Tab order.
- The deletion is permanent, with no trash and no undo.

**Quit during a run.**
- Quitting with ⌘Q, Alt+F4 or the close button silently stops the run and deletes its test data.
  It should ask first.

**Settings.**
- Settings is an in-window modal with a Done button.
- macOS expects a separate window that applies changes live. GNOME expects a preferences dialog.

**Menus off macOS.**
- The primary menu is five submenus; GNOME expects a flat menu in sections.
- It pops up at the pointer rather than below its button.
- There is no About dialog.
- Quit is Alt+F4 rather than Ctrl+Q on GNOME, and is not called "Exit" on Windows.
- There is no full screen.
- **(mac)** Menu items with a role (Undo, Quit, …) follow the system language, not the app's
  language.

**State and scaling.**
- The window size and position, the sidebar and the page are never restored.
- Fixed control heights clip text when Windows text scaling is above 100 % **(win)**.
- The toolbar is 52 pt high on every platform; Windows uses 32 or 48 and GNOME about 46.
- The sidebar has a fixed width and cannot be resized.

**Files.**
- "Open" reads the whole file into memory through the image picker, with no file-type filter.
- Opening from Finder or Explorer ("Open With", double-click) is not handled.
- There is no highlight when a file is dragged over the window.

**Contrast.** These fail WCAG:

| Element | Colours | Ratio |
|---|---|---|
| Dark-mode selected row | white on `#3d95f5` | 3.08 : 1 |
| Field and switch borders | `#d2d2d8` on white | 1.51 : 1 |
| `warn` text at 11 pt | | 3.99 : 1 |

**Selection style.**
- The filled accent row is macOS style only; GNOME and Fluent use a subtle fill.
- **(mac)** Selected rows should turn grey when the window is not key.

**New Run.**
- The workload control wraps onto two lines; it should be a native pop-up (`nsh_base::select`).
- The lab scenarios are six toggle buttons.
- The operator field is not focused when the dialog opens.
- Return works only inside that one field.

**Feedback.**
- When a run ends while the window is in the background, there is no notification and no Dock or
  taskbar attention.
- The notice bar is not announced to screen readers.

**Smaller issues.**
- Charts have no accessible role or label.
- The selectable title swallows the title bar's double-click.
- The modal fade ignores reduced motion.
- A secondary click does not highlight the row it acts on.
- On wide windows the detail leaves an empty band.

## 4. Plan for 6.3

There are no new commands, findings or formats. Every item below removes a confusion, fixes a
wrong number or follows a platform rule.

### A. Correctness and trust (first)

1. **The timeline means what it says.**
   - Goodput excludes failures.
   - Throttled counts responses.
   - Requests, throttling and failures land in the interval they happened in.
   - Add requests per second and retries per interval. Rate limits become visible, and
     `lab://ratelimit` is diagnosed as one.
2. **The demo proves.**
   - Recalibrate `lab://demo` so that its top finding proves `improved`.
   - Severity follows the cost of a problem (backoff share, failed operations), not merely its
     presence.
   - A convergence test runs `demo` → `prove last`, and the README shows real output.
3. **One prove path.**
   - The app's Apply means "prove this finding": `ProveRequest.finding`, sized the same way as in
     the CLI. Delete `suggested()`.
   - One budget flag (`--max-duration`).
   - The ETA covers the whole proof.
   - With 0 pairs, print "not measured" and no diff.
4. **Honest distributions.**
   - Keep the run's histogram in the report and draw the CDF from it.
   - Use the fine heatmap rows when every row was kept, and add a legend.
   - Mute per-interval quantiles when an interval has too few operations.
   - Compare stays neutral (no colours) and points to prove.
   - Weight sampled rows in findings.

### B. Observability without clutter

5. **Brush and link.**
   - Drag across any timeline or the heatmap to select a time range. Every chart shares one
     crosshair.
   - The numbers, tables, CDF and waterfalls then recompute for that range from the trace rows.
   - Add `show --since/--until` to the CLI.
6. **Drill down.**
   - Each finding gets "Show N examples", from its `op_ids`.
   - Clicking a heatmap cell or an API row lists its slowest requests.
   - Hovering a request in the waterfall shows its provider error code, Retry-After, rtt and
     retransmits, and Server-Timing.
7. **One verb / API filter** above the timeline. This needs per-verb counters per interval.
8. **Quick fixes.**
   - The column headings say which share they are.
   - The finding texts: the `repeated_reads` unit, the doubled `key_limit` remedy, and every API
     for `tail_stragglers`.
   - The CLI timeline keeps its interval length, gains p99.9 and max, and is downsampled for long
     runs.
   - `show --detail` gains a Spread section.

### C. Native quality

9. **Sidebar.**
   - Real material: stop painting the root, and use Mica on Windows.
   - A keyboard listbox with arrows, Shift, type-select, Delete and the right roles.
   - Selection styled per platform, inactive grey on macOS, and a width the user can resize.
10. **Safe destructive actions.**
    - Delete uses `alert_dialog`, with Cancel as the default, and moves runs to the trash with
      Undo.
    - Menu shortcuts do not fire while the user is typing.
    - Quitting or closing during a run asks first.
11. **Settings and menus.**
    - Settings is its own window on macOS and a preferences dialog on GNOME.
    - GNOME and Windows get a flat primary menu anchored under its button, with About, Ctrl+Q or
      Exit, and full screen.
    - Menu items with a role are labelled in the app's language.
12. **Platform details.**
    - Restore the window and the view state.
    - Size controls from the font scale, and give the toolbar each platform's height.
    - New Run uses `select` and a combobox, focuses its first field, and takes Return.
    - Open uses a path picker with a filter, opens files from Finder or Explorer, and highlights a
      drag over the window.
    - Fix the contrast tokens.
    - Notify when a run ends in the background, and announce errors to screen readers.
13. **Platform tests.** Add headless UI tests that run as macOS and as Windows, for menus,
    shortcuts and dialog button order.

### D. Simplify

14. **One vocabulary everywhere.**
    - Verdicts: ok, review, attention, critical.
    - Prove results: improved, worse, inconclusive.
    - Trials are called "trial".
15. **Remove 5.x vestiges.**
    - Remove the SLA surface, run labels, dead finding titles, and `[operators.NAME]`. A path to an
      `op.toml` covers the last.
    - Offer the same six lab scenarios in the CLI and the app.
16. **Output.**
    - Never truncate when stdout is not a terminal.
    - Diffs show only values that differ from the defaults.
    - The S3 error code comes first in errors.
17. **New Run in the app plans first** for real targets, and lists the configured operators and
    `op.toml` files.

### Order

- **6.2.1:** the macOS menu bar (PR #24), now.
- **6.3:** sections A and C first, because they are wrong numbers and broken platform behaviour,
  then B and D.
- Two items change the formats (`oprobe.report/6`, `oprobe.run/6`), both additively:
  - A1 adds per-interval fields.
  - A4 adds a histogram.

  Both stay within 6.x.
