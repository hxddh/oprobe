# oprobe 9.3 review: what 9.4 should be

Status: proposal, for the owner to accept. Date: 2026-11-27. Basis: 9.3.3 (`e24b2e5`).

The review had three sources:
- **A hands-on run of the release binary as a new user would**. It covered every command's help,
  the README and getting-started examples as written, the demo and ten labs, each followed to the
  `next` it printed, `-o json` everywhere, and the error paths. It used no cloud credentials.
- **An upstream read** of OpenDAL 0.59.5 (the latest release) and OpenDAL `main` (`59faed4`,
  unreleased), hyper 1.13.0, reqwest 0.13.5, foyer 0.22.6, opentelemetry 0.33 and rustls 0.23.
  Each was read against what oprobe wires.
- **The release of 9.3.3 itself**: its CI, its two release runs, and what the code review behind
  it left open.

Each item says how sure it is:
- **reproduced**: seen on the 9.3.3 binary;
- **read**: the code path traced;
- **suspected**: what would confirm it is named.

## Direction

The loop is right, and the stop paths and the statistics are now sound. What a user meets first
is where the remaining gap is:
- on two of ten labs the top finding or its proof points the wrong way;
- a few numbers are absurd;
- every capacity question still needs a second run, the oldest known issue (9.1, 9.2 and 9.3
  list it).

**9.4 is a "right the first time" release.** It adds no command, no flag and no format bump.

1. **Explain is never wrong on a lab** (stream E). Every lab's top finding is its fault, and every
   printed `next` proves improved, or says plainly why it cannot.
2. **One run answers capacity** (stream C). The warm-up ramps the load, so the queueing and
   capacity fits work on any run.
3. **Nothing reads like an internal** (stream U). No serde text, no raw JSON, no self-referencing
   hints, no unlisted labs.
4. **Ride OpenDAL's next release, don't chase it** (stream O). Take the fixes that are free now,
   and prepare the 0.60 migration that unlocks a better cache remedy.
5. **A release that cannot surprise** (stream R). 9.3.3 lost a release run to untested workflow
   shell.

**Not in 9.4:**
- new commands, flags, presets or output formats (v6 §1);
- OpenTelemetry spans or any export beyond today's metrics (v6 §1: not a monitoring system);
- a second remedy per finding;
- AIMD pacing and hedged reads as remedies until a lab proves they beat today's remedy (O4);
- renaming the JSON fields that break the unit-suffix rule (U9: it needs a format bump; collect
  them for the next one).

**The finish line, measured on the labs** (it replaces "it feels done"):
- the top finding matches the fault on all 13 labs;
- every printed `next` decides, and no proof marked `improved` costs more than 10 % on its
  secondary objective without saying so in the verdict;
- no stderr line contains `{`, `untagged`, `Raw` or an internal type name;
- from install to first finding takes under 30 s, and `demo` and its proof stay under 60 s.

## What holds

- **Most labs are right the first time.** demo, throttle, stragglers, bandwidth, flaky,
  ratelimit and hotkey each name their fault as the top finding. Every printed `next` ran as
  printed. ETAs held on 7 of 9 proofs.
- **Machine output is clean.** stdout carries one JSON document for run, demo, prove, show, lab
  and errors, with progress on stderr.
- **Errors are fast and classified.** An unreachable endpoint fails in 34 ms with
  `net.unreachable`. Unknown schemes, unknown `--set` keys, bad presets, bad sizes and a `--since`
  past the window are all clear, with exit 2.
- **Files are portable.** A copied `.oprobe` file opens; `--since`/`--until` work; `show --rm`
  removes a prove's trials too.
- **The 9.3.3 fixes held through release.** On every OS, test, convergence, the real backends
  (MinIO, fake-gcs-server, Azurite), the 1.48 µs/op overhead and the release builds all passed.
- **Dependencies are current.** OpenDAL 0.59.5, reqwest 0.13.5, foyer 0.22.6 and rustls 0.23 are
  the latest releases. Only hyper is one release behind (1.12 → 1.13).

## C. One run answers capacity

The known issue that 9.1, 9.2 and 9.3 all carry: a steady closed loop cannot tell too few workers
from a saturated service, and the queueing and capacity fits need a run whose load varied. Users
get "the load was not varied: rerun with `--set shape=ramp:…`". That is a second run, and a flag
value nobody guesses.

| # | Item | Fix |
|---|---|---|
| C1 | **The warm-up ramps.** It runs today at full concurrency and is thrown away | Ramp it in steps (1, 2, 4 … `-c` workers, each step a few hundred operations or a time slice), record the steps, and feed them to the capacity fits as a varied-load sample. The measurement window is unchanged, so no number in the report moves. No flag: it is how the warm-up works. The 9.2 review named this as "a design item for after 9.3" |
| C2 | **Then the headline answers the question it now defers.** The "inconclusive: latency grows with the requests in flight" and "load was not varied" lines disappear on runs that warmed up | Delete the deferral wording and the `shape=ramp` hint from the healthy-run brief once C1 lands; keep `shape` for users who want an explicit ramp |
| C3 | **The ramp's suggested window** stayed 3.0 s on `--set shape=ramp:50..800/6s` | Check that a ramp's duration sets the window (suspected: the window took the preset's) |

## O. Ride OpenDAL's next release, don't chase it

OpenDAL `main` is well ahead of 0.59.5. Everything below marked *unreleased* waits for 0.60, and
9.4 must not depend on a git version of OpenDAL.

| # | Item | Gain | Cost | When |
|---|---|---|---|---|
| O1 | **hyper 1.13.0** (released 2026-11-23): an HTTP/2 request parked on a closing connection now fails instead of hanging (#4275, #4242); an HTTP/1 body shorter than its Content-Length now errors (#4270) | Fewer false `hung_requests` under `http.version=h2`, and truncated bodies classified right. A lockfile bump | none | 9.4 |
| O2 | **Drop the unused `layers-await-tree` feature** (the layer is deliberately not used: −14 % throughput) | Compile time | none | 9.4 |
| O3 | **`CacheLayer` replaces the deprecated `FoyerLayer`** (*unreleased*, #9185, #9164). It caches 1 MiB object-aligned chunks of sources with a verifiable identity (version, strong ETag, or mtime and length), with a metadata TTL | `repeated_reads` → `layers.cache` then works for range and parquet reads. Today `build.rs:344-390` refuses or caps the cache because FoyerLayer fetches whole objects. Same remedy path; the emitted Rust stops recommending a deprecated API | low | with OpenDAL 0.60: prepare the code path and the lab behind the version bump |
| O4 | **`AimdLayer` (adaptive pacing honouring Retry-After) and `HedgeLayer` (hedged stat/read)** (*unreleased*) | Possibly better remedies for `throttling`/`rate_limit` (a limit that drifts) and `tail_stragglers` (reads) | medium: the one-remedy rule means either *replaces* today's remedy, never sits beside it | evaluate in the labs (`timevarying` for AIMD, `stragglers` for hedging) once 0.60 is out; switch a remedy only if `prove` shows it beats the current one on its own lab |
| O5 | **RFC-9061 unified operator config** (*unreleased*, #9171-9173): `from_uri`/`via_iter` accept `layer.<name>.<field>` and `context.http.*` | A third rendering of the same proven diff (config keys), so Python, Java and Node users can apply a remedy (v6 §1 names them). tail_cut, cache, `http.version` and keep-alive have no keys: the diff says "Rust only" for those | low | with 0.60 |
| O6 | **The concurrent deleter** (`deleter_with().concurrent(n)`, *unreleased*, #9118) | Faster cleanup of large datasets; internal only | none | with 0.60 |
| O7 | **0.60 migration risks**, to test before switching: OpenDAL's MSRV moves to 1.95 (oprobe-trace advertises 1.91); `opendal-layer-otelmetrics` moves to opentelemetry 0.33.1, and oprobe-trace's 0.32 pin must move in step (a semver-visible change of the `otel` feature); `ConcurrentLimitLayer`'s HTTP transport type is no longer public (`QueueStampLayer` assumes its position); `RetryLayer` is rewritten (the tail-cut message matching in `record_retry_with_cut` must be re-checked); `TailCutLayer` keeps per-operation histograms on the context executor's timers (the shared pre-warmed layer and prove numbers may move); 307/308 replay the body | | | a `0.60` branch, CI against OpenDAL `main` weekly (allowed to fail), so the migration is known before the release |

Considered and left out: OpenDAL's own metrics and tracing layers (they duplicate oprobe-trace,
and v6 §1 rules them out); `prefetch` (oprobe's workloads collect whole buffers and could never
show its effect); the hidden `stat` of an unbounded range (`content_length_hint`: per call, so
advice at most, and rare).

## R. A release that cannot surprise

| # | Issue | Fix |
|---|---|---|
| R1 | **9.3.3's first release run failed in shell no test ran** (`if x=$(a \| b)`), after 70 minutes of builds. The fix was right, but the workflow's logic is still untested YAML | Move each release step's logic into `scripts/release/*.sh` (plan, tag, manifests), shellcheck them in CI, and unit-test plan and tag against a local bare repository (tag missing, tag present on the same commit, tag on another commit) |
| R2 | **`oprobe-trace` has never been on crates.io** (no `CARGO_REGISTRY_TOKEN`). Embedding needs a git dependency, and docs.rs has no page | The owner adds the token (a decision, not code). Everything else is ready: `cargo package` passes, and the docs test switches the snippet once the crate exists |
| R3 | **CI warns that its actions run on deprecated Node 20** | Bump the pinned action SHAs to their Node 24 releases |
| R4 | **`oprobe-core` has 19 rustdoc warnings** (broken intra-doc links), because its docs build without `-D warnings` | Fix them; build both crates' docs with `-D warnings` |

## What stays as it is

The command set (run, prove, show, lab, the app), the four presets, the finding catalog's 13
codes and their remedies, the file formats, and the trace layer's API. Nothing in this review
asks for more of them. Each item above makes an existing answer right, readable or cheaper.

## Plan for 9.4

| Stream | Items | Size |
|---|---|---|
| **E: Explain** | E1 to E8 | medium; the centre of the release. E3 first (it may change what a proof means) |
| **C: capacity in one run** | C1 to C3 | medium |
| **U: wording** | U1 to U8 and U10 to U13; U9's test | small each |
| **O: upstream** | O1, O2 now; O3 to O7 prepared on a 0.60 branch | small now, medium with 0.60 |
| **R: release** | R1, R3, R4; R2 is the owner's | small |

Order: E1 and E6 (wrong answers a user meets in the first minutes), then E3 (confirm or drop),
then C1, then U. Each fix comes with a test that fails on 9.3.3. Each lab result in the finish
line is checked by `tests/convergence.rs`, which grows a case per lab that has none (noisy,
hotkey, queueing).
